# Подключение общего рейтинга — проверено 20 ноября 2026, 0.201

Адаптер есть, живой рейтинг ещё не активирован. Карточка игры, серверная таблица и токен не созданы; игра не публиковалась. Для Playgama нужно подключить Bridge SaaS, одного локального ID в конфигурации недостаточно.

## Правило

`red_kills_v1`: число побеждённых обычных красных врагов за один законченный обычный забег, включая поражение. Боссы отдельно. Больше — лучше. Отправляется личный максимум, а не сумма всех забегов. На стороне таблицы нужна сортировка по убыванию и сохранение лучшего значения, чтобы повторная отправка/второе устройство не ухудшали результат.

1. Создать карточку в кабинете Playgama. В разделе **Bridge SaaS → Leaderboards** создать таблицу с ID `red_kills_v1`; публичный токен находится наверху той же страницы. Секретный ключ не вставлять в клиент.
2. Добавить в playgama-bridge-config.json объект `saas` с реальным `publicToken` и `leaderboards: {"platforms":["playgama","qa_tool"]}`. Сохранить корневую запись `leaderboards` с `id: "red_kills_v1"`. Сейчас фиктивный токен в конфигурацию не добавлен. Это [официальная схема SaaS](https://wiki.playgama.com/playgama/bridge-sdk/saas/leaderboards).
3. Загрузить содержимое `dist/playgama/`: index.html и playgama-bridge-config.json. Это отдельная сборка с Bridge v2, не локальный `_QA.html`.
4. В QA Tool проверить identity игрока, доступность leaderboard type, запись результата, таблицу с двух аккаунтов, более низкий результат после высокого, потерю сети/повтор, перезапуск и полный отказ API.
5. Только после проверки разрешать публикацию. Здесь live-проверка не выполнялась.

`setScore` вызывается только при завершении допустимого забега; ошибка оставляет pending. Повтор — через кнопку «Обновить» в рейтинге. На `in_game` игра рисует строки реальных данных `getEntries`; на `native_popup` открывает окно площадки; на `native` поясняет, что рейтинг отображает площадка. При `not_available` или в локальном файле показаны только личные забеги с явной подписью. QA сборка полностью запрещает сетевую отправку, даже если подменить флаг testRun у героя. Исторические очки из лагеря не мигрируют: нельзя достоверно выделить из них убийства красных и честные забеги.

Клиент отсеивает известные админ-забеги и некорректные значения, но это не криптографически защищённый рейтинг. Для призов/денежных соревнований необходима отдельная серверная проверка результатов; её здесь нет.

API сверено с первичным исходником [Playgama Bridge LeaderboardsModule](https://github.com/Playgama/bridge/blob/main/src/modules/leaderboards/LeaderboardsModule.ts) и [типами записей](https://github.com/Playgama/bridge/blob/main/src/modules/leaderboards/types.ts): setScore(id, score), getEntries(id), showNativePopup(id); поля id/name/score/rank/photo. Сторонний код в игру не копировался.
